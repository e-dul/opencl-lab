# Scripts

The `scripts/` directory contains helper utilities for building the lab, running tests, tracking design progress, and generating asset files consumed by OpenCL modules. All commands below are meant to be run from the **repository root**.

---

## build_all.sh

**Purpose:** Configure and build modules 0 and 1 using the top-level CMake project.

**Prerequisites:**
- CMake 3.18+
- An OpenCL-capable driver and SDK (headers + ICD loader)

**Usage:**
```bash
bash scripts/build_all.sh
```

**Expected Output:**
Binary artifacts appear under `build/`. Only `BUILD_MODULE_0` and `BUILD_MODULE_1` are enabled; all other module flags (`BUILD_MODULE_2`, `BUILD_TOOLBOX`, `BUILD_ADDONS`) default to `OFF`. This is intentional — the script is a quick sanity-check build, not a full-lab build. To build additional modules, pass `-DBUILD_<MODULE>=ON` to CMake directly or edit the script.

---

## test_all.sh

**Purpose:** Execute the CTest suite for whatever modules were previously built.

**Prerequisites:**
- A complete prior build: `cmake -B build && cmake --build build` (or `bash scripts/build_all.sh`).
- The `build/` directory must exist with CTest metadata generated by CMake.

**Usage:**
```bash
bash scripts/test_all.sh
```

**Expected Output:**
CTest output for each registered test, with failures printed inline (`--output-on-failure`). A summary line (`X tests passed, 0 tests failed`) is printed at the end.

## progress.sh

**Purpose:** Report checkbox completion across all design documents in `workflow/design/`.

**Prerequisites:**
- Bash 4+ (uses associative arrays)
- `workflow/design/*.md` files with `- [x]` / `- [ ]` checkbox items

**Usage:**
```bash
bash scripts/progress.sh
```

**Expected Output:**
A formatted table with one row per design document. Each row shows the document title, completed/total task counts, an ASCII progress bar, and a percentage. A `TOTAL` summary line appears at the bottom. Example:

```
Applied OpenCL Lab — Progress Report
Module                                                   Tasks  Progress

 ✓ D01 — Host API                                        6/6   [####################] 100%
 ~ D09 — Cookbook v2.0                                   6/15  [########............]  40%
────────────────────────────────────────────────────────────────────────────────
 TOTAL: 12/21 tasks done  [###########.........] 57%
```

## gen_pgm.py

**Purpose:** Generate a synthetic binary occupancy-grid map in PGM format (convention: 255 = free, 0 = obstacle) for use with the ROS 2 Robotics modules.

**Prerequisites:**
- Python 3.6+
- No third-party packages required (stdlib only)

**Usage:**

Canonical invocation that writes the asset used by `04_Robotics/`:
```bash
python3 scripts/gen_pgm.py -o assets/warehouse.pgm --width 512 --height 512
```

Optional flags:
```bash
# Smaller map, no outer border wall
python3 scripts/gen_pgm.py -o assets/warehouse.pgm --width 256 --height 256 --no-border
```

**Expected Output:**
A binary PGM file (`P5` header) at the specified path. Console confirmation:
```
Wrote assets/warehouse.pgm (512x512, 5 obstacle rects, border)
```

## gen_bayer.py

**Purpose:** Demosaic a 4K RGB BMP image into a raw single-channel Bayer-pattern file (`RGGB`, 8-bit) consumed by the SoftISP module (`02_Multimedia/09_SoftISP`).

**Prerequisites:**
- Python 3.6+ (stdlib only — uses `struct` and `pathlib`)
- `assets/rgb_4k.bmp` must exist at the repository root before running. Generate it with your preferred tool (e.g. ImageMagick: `convert your_source.jpg -resize 3840x2160! assets/rgb_4k.bmp`).

**Usage:**
```bash
python3 scripts/gen_bayer.py
```

The script has no CLI flags. Input and output paths are fixed:
- Input: `assets/rgb_4k.bmp` (3840 × 2160, 24-bit BGR BMP)
- Output: `assets/raw_bayer_4k.raw` (8 294 400 bytes, one byte per Bayer pixel)

**Expected Output:**
```
raw_bayer_4k.raw written: 8294400 bytes
```
