## Context

The existing modules partially use ament_cmake infrastructure (`find_package(ament_cmake)`, `ament_target_dependencies` via `opencl_lab_ros2_target`) but are missing the three things that make a directory a real ROS 2 package: `package.xml`, `ament_package()`, and installed targets. Adding these three, switching from `add_executable` to `add_library(SHARED)` + `rclcpp_components_register_node`, and writing composable launch files is the complete migration.

The `opencl_lab_ros2_target` macro already calls `ament_target_dependencies` with the plain-form signature. It continues to work with `SHARED` library targets unchanged. The `opencl_lab_ros2_guard()` macro continues as the ROS environment guard. `common/` headers are accessed via relative path — `../../common` — with no ament package wrapping.

## Goals / Non-Goals

**Goals:**
- `ros2 launch <package> <file>` works from any directory after sourcing install
- `ros2 component load /ComponentManager <package> <Plugin>` works
- `colcon build` from within each module directory builds that package in isolation
- Intra-process zero-copy between node and companion publisher in same container
- `auto_activate` parameter exposes self-managed and externally-managed lifecycle
- YAML parameter files included per module

**Non-Goals:**
- `common/` as an ament package
- `nav2_lifecycle_manager` or bond/heartbeat lifecycle
- Shared workspace (each module remains independently buildable)
- Per-stage kernel timing changes (OpenCL code unchanged)
- QoS changes (separate `ros2-qos-profiles` change)

## Decisions

### D1: Package naming — snake_case, matches executable name

**Decision**: Package names match the existing executable names: `node_acceleration`, `costmap_inflation`, `perception_node`, `voxel_mapping`.

**Why**: `project()` in CMakeLists currently uses PascalCase (`NodeAcceleration`) per lab convention, but ROS 2 package names must be snake_case. The `package.xml` `<name>` field is the ROS 2 package name and uses snake_case. The CMakeLists `project()` call is updated to match. Plugin identifiers use `<package>::<ClassName>` (e.g., `perception_node::PerceptionNode`).

### D2: `add_library(SHARED)` + `rclcpp_components_register_node` pattern

**Decision**: Each node becomes a shared library. `rclcpp_components_register_node` generates both a composable plugin and a standalone executable wrapper:

```cmake
add_library(perception_node SHARED main.cpp)
target_compile_definitions(perception_node PRIVATE "COMPOSITION_BUILDING_DLL")
rclcpp_components_register_node(perception_node
  PLUGIN "perception_node::PerceptionNode"
  EXECUTABLE perception_node_exe)
```

The generated `perception_node_exe` is a thin wrapper that launches a single-node component container — useful for debugging without a full launch file.

**Why**: `rclcpp_components_register_node` with `EXECUTABLE` gives both composition and standalone use from a single registration. No duplicate `main()` to maintain.

**Alternative considered**: Keep `add_executable` + add `rclcpp_components_register_node` separately — rejected; this creates two independent binaries with no shared build artifact.

### D3: `main()` removal

**Decision**: Remove `main()` from all node source files. The component container and the generated `_exe` wrapper replace it entirely. Companion publishers lose their `main()` identically.

**Why**: With `rclcpp_components_register_node` the `main()` is generated by the macro. Two `main()` definitions in the same TU → linker error.

**Exception**: For the companion publishers that are NOT ROS nodes but CLI tools (none in this set — all companions are `rclcpp::Node` subclasses), `main()` would stay. All companions here are nodes; all lose `main()`.

### D4: Companion publishers as composable components

**Decision**: `synthetic_publisher`, `map_publisher`, `point_cloud_publisher`, `voxel_point_cloud_publisher` each get `RCLCPP_COMPONENTS_REGISTER_NODE` and are registered in the same package. The launch file loads both the main node and its companion into one `ComposableNodeContainer`.

**Why**: Same container = intra-process zero-copy. For C3, this eliminates ~1.2 MB DDS serialisation per PointCloud2 message at 100k points. For C1/C2, it preserves the existing zero-copy guarantee without requiring a single compiled binary.

**Note**: CLI11 args in companion publishers (`--scene`, `--hz`, `--points`) must be converted to `declare_parameter` as part of this migration (companions become nodes; hand-rolled arg parsing is forbidden per spec). Parameters are then passed via launch file.

### D5: `auto_activate` parameter

**Decision**: Declared in `on_configure()` for all LifecycleNodes (C1, C2, C3). Default `true`. When `true`, the existing one-shot wall timer fires immediately to call `trigger_transition(ACTIVATE)`. When `false`, no timer is started — the node waits for external lifecycle management.

```cpp
// In on_configure():
declare_parameter("auto_activate", true);
if (get_parameter("auto_activate").as_bool()) {
    activate_timer_ = create_wall_timer(std::chrono::milliseconds(0), [this]() {
        activate_timer_->cancel();
        trigger_transition(lifecycle_msgs::msg::Transition::TRANSITION_ACTIVATE);
    });
}
```

**Why**: Same deadlock-safe pattern already in C3. Runtime switchable via launch arg or `--ros-args -p auto_activate:=false`. No compile-time branching.

**Note**: Voxel Mapping is a plain `rclcpp::Node` — no lifecycle, no `auto_activate`.

### D6: Kernel and asset installation

**Decision**: `symlink_kernels` and `symlink_assets` continue for the build tree (development). For the installed tree, add:

```cmake
install(DIRECTORY kernels/ DESTINATION share/${PROJECT_NAME}/kernels)
```

The node's `get_binary_dir()` call (from `opencl_utils.hpp`) may need to be supplemented with a `get_package_share_directory`-style path for installed kernels. Use `ament_index_cpp::get_package_share_directory` as a fallback when the build-tree symlink is absent.

**Alternative considered**: Require building in-place only — rejected because `ros2 launch` after `source install/setup.bash` uses the installed tree, not the build tree.

### D7: `colcon build` from module directory

**Decision**: Each module is its own colcon workspace. Running `colcon build` from `04_Robotics/01_Node_Acceleration/` finds the `package.xml` and builds only that package. `build/`, `install/`, `log/` land in the module directory.

**Why**: Preserves the standalone-recipe educational model. 1:1 replacement for `cmake -B build && cmake --build build`. `source install/setup.bash` replaces `./build/<binary>` as the prerequisite for `ros2 launch`.

### D8: `opencl_lab_ros2_target` macro — library target compatibility

**Decision**: The existing macro uses `ament_target_dependencies` (plain-form) which is target-type agnostic. No change needed to the macro itself. Add a new `opencl_lab_ros2_install` macro to `common.cmake` for the install + ament_package boilerplate.

```cmake
macro(opencl_lab_ros2_install TARGET_NAME)
    install(TARGETS ${TARGET_NAME} EXPORT export_${TARGET_NAME}
        ARCHIVE DESTINATION lib
        LIBRARY DESTINATION lib
        RUNTIME DESTINATION lib/${PROJECT_NAME})
    install(DIRECTORY kernels/ DESTINATION share/${PROJECT_NAME}/kernels)
    ament_package()
endmacro()
```

**Why**: Keeps CMakeLists per-module thin; the install pattern is identical across all four modules.

### D9: YAML parameter files (absorbed from ros2-launch-files D7)

**Decision**: Each module gets `config/<package_name>.yaml` with parameter defaults. Launch file loads it via `parameters=[get_package_share_directory('<pkg>') + '/config/<pkg>.yaml']`. Per the spec absorbed from ros2-launch-files, launch argument overrides take precedence.

### D10: Launch file structure

**Decision**: `ComposableNodeContainer` with `intra_process_comms=True`:

```python
ComposableNodeContainer(
    name='<pkg>_container',
    namespace='',
    package='rclcpp_components',
    executable='component_container',
    composable_node_descriptions=[
        ComposableNode(package='<pkg>', plugin='<ns>::<NodeClass>',
                       name='<node_name>',
                       parameters=[yaml_path, launch_arg_overrides],
                       extra_arguments=[{'use_intra_process_comms': True}]),
        ComposableNode(package='<pkg>', plugin='<ns>::<PublisherClass>', ...),
    ],
)
```

RViz2 is a separate `Node` action (not composable). `gpu` launch arg sets the `GPU` env var via `additional_env` on the container node.

## Risks / Trade-offs

- **`source install/setup.bash` friction**: Students must source before `ros2 launch`. → Mitigation: update all READMEs; add a one-line reminder to the colcon build output via `message(STATUS ...)`.
- **Kernel path in installed tree**: `get_binary_dir()` returns the install lib dir, not the share dir. → Mitigation: D6 fallback via `ament_index_cpp`.
- **CLI11 removal from companion publishers**: companions currently use CLI11 for `--scene`, `--hz`, etc. Converting to `declare_parameter` is required by spec (ROS 2 exemption) and is already done for Voxel Mapping main node in `ros2-param-improvements`. → These conversions are part of this change's task scope.
- **`colcon build` from package directory**: less common than workspace-root builds but fully supported by colcon. → Document clearly in each README.
- **`ros2-launch-files` paused artifacts**: D1 is obsolete; D7 absorbed here. The paused change should be archived as superseded after this lands.
